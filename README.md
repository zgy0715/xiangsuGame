# 像素填空 (Fill-a-Pix)

> 逻辑与像素的碰撞 —— 一款基于数字线索推理的 Android 像素画解谜游戏

Fill-a-Pix（像素填空）是一种经典逻辑谜题：棋盘上的每个数字提示告诉你在它周围 3×3 区域内需要涂黑的格子数量，玩家通过逻辑推理确定每个格子的状态，最终拼出一幅完整的像素画。

本项目使用 **Kotlin + Jetpack Compose** 实现，逻辑层与 UI 层完全分离，核心算法（提示推导、唯一解校验、精确错误检测）可独立进行单元测试。

## ✨ 功能特性

- **双身份登录**：👤 玩家（顺序解锁、无特权）/ 👑 管理员（密码登录、全局解锁含隐藏关），首页显示身份徽章
- **三态方格**：未确定 / 涂黑 / 标记空白，单击循环切换
- **长按快捷操作**：长按直接标记为空白
- **撤销 / 重做 / 重置**：基于指令栈的标准操作历史（一键补齐整批可一步撤销）
- **错误提示**：实时按答案逐格标红"画错的格子"（红叉 + 红框，可开关），未决定的格子不误报
- **已满足提示**：某提示周围窗口已确定且数量达标时数字变绿，经典解谜反馈
- **一键补齐**：⚡ 自动补全本关全部正确像素；全局仅 2 次、所有关卡共用、不可刷新，次数用尽按钮自动灰化
- **全局计时**：所有关卡实时计时（mm:ss），通关 / 退出 / 重开时停止归零
- **双模式**：🎮 自由模式（不限时）/ ⏱ 限时模式（按难度配时限，超时判失败，倒计时低于 1 分钟变红）
- **关卡制**：10 个常规关 + 1 个隐藏关（城堡 64×64），由易到难递进
- **稀疏提示**：只在部分格子放数字，棋盘清爽、推理更有乐趣；每关谜面经"贪心去提示 + 唯一解校验"生成，保证有且只有唯一解
- **顺序解锁 + 存档**：通关第 N 关解锁第 N+1 关；隐藏关需通关全部 10 关（管理员直接解锁）；进度本地保存，重启保留
- **参考答案**：随时查看完整像素画，看过会在结算中标注
- **通关揭晓**：通关后棋盘直接呈现干净完整的像素画
- **游戏化界面**：靛紫品牌配色主题（浅色 / 深色）+ 游戏开场登录页（渐变 Hero + 真实图案像素画装饰）+ 首页关卡网格（难度星级 / 锁定状态 / 通关即揭晓像素画 / 隐藏关金色描边）+ 游戏页 HUD 计时与进度条 + 点击触觉反馈

## 🎮 玩法规则

1. **读提示**：棋盘上每个格子显示一个数字（0~9），表示以该格为中心的 3×3 区域内必须恰好涂黑 N 格；`-1` 表示无提示。
2. **推理涂黑**：根据数字约束推断哪些格子应当涂黑、哪些应当留白。
3. **完成目标**：将所有应涂黑的格子涂黑（空白格保持不涂黑），即可还原出完整的像素画并通关。

### 操作说明

| 操作 | 效果 |
|------|------|
| 单击 | 循环切换：空白 → 涂黑 → 标记空白 → 空白 |
| 长按 | 直接标记为空白 |
| 撤销 / 重做 | 回退 / 重放最近操作 |
| 重置 | 清空棋盘并归零计时 |
| 错误提示开关 | 开启后实时标红"画错"的格子（红叉 + 红框，精确到单格） |
| 一键补齐 | ⚡ 自动补全本关全部正确像素（消耗 1 次全局额度，可一步撤销） |

> 提示：解谜过程中多数中间状态天然不满足全部数字约束（因为还没画完），
> 因此错误提示采用"按答案逐格比对"——只标红玩家已提交但画错的格子（误填的涂黑 / 误标的空白），
> 未决定的格子不算错，避免干扰正常推理。

### 身份与模式

- **登录**：启动即进入登录页。**玩家**点一下即进，按顺序解锁；**管理员**需输入密码（默认 `admin`），全局解锁全部关卡（含隐藏关），自由 / 限时模式通用。
- **限时挑战**：首页顶部切换 🎮 自由 / ⏱ 限时。限时模式每关按难度配时限，超时判失败（自动结束本局，不写入通关进度）；倒计时低于 1 分钟变红提示。
- **一键补齐额度**：全游戏共 2 次，所有关卡（含限时模式）共用，不支持单关重置、不支持刷新，持久化保存，重启不恢复。

## 🏗️ 项目架构

项目采用**模型-视图分层**，逻辑与界面完全解耦：

```
app/src/main/java/com/example/xiangsugame/
├── MainActivity.kt          # 应用入口 + 页面导航（登录 → 首页 ⇄ 游戏页）
├── GameProgress.kt          # 关卡进度 + 一键补齐额度（SharedPreferences 持久化 + 顺序解锁）
├── model/                   # 核心逻辑层（纯 Kotlin，无 UI 依赖）
│   ├── CellState.kt         # 方格三态枚举（未确定/涂黑/标记空白）
│   ├── UserRole.kt          # 登录身份枚举（玩家 / 管理员）
│   ├── GameMode.kt          # 游戏模式枚举（自由 / 限时）
│   ├── Level.kt             # 关卡数据（提示矩阵 + 答案矩阵 + 隐藏关/时限）
│   ├── GameBoard.kt         # 棋盘状态容器 + 撤销/重做指令栈（含批量补齐）
│   ├── PuzzleGenerator.kt   # 由答案像素图推导提示数字（全量 / 稀疏）
│   ├── PuzzleSolver.kt      # 回溯 + 约束传播求解器（校验谜面唯一解，可选限时）
│   ├── Validator.kt         # 精确错误检测 + 已满足提示检测 + 胜利判定
│   ├── Levels.kt            # 内置 10 常规关 + 1 隐藏关（大尺寸用程序化作画）
│   └── SparseClues.kt       # 各关稀疏提示位置（生成器产物，保证唯一解）
└── ui/                      # 界面层（Jetpack Compose）
    ├── LoginScreen.kt       # 登录页（玩家一键 / 管理员密码）
    ├── HomeScreen.kt        # 首页关卡网格（身份徽章 / 模式选择 / 星级 / 锁定 / 隐藏关）
    ├── GameScreen.kt        # 游戏页（HUD 计时、限时倒计时、一键补齐、撤销重做、结算）
    ├── BoardView.kt         # Canvas 棋盘渲染 + 手势交互 + 迷你像素画预览
    └── theme/               # 游戏靛紫品牌配色主题（浅色 / 深色）
```

> `tools/` 目录提供图案渲染 / 稀疏提示再生成的开发脚本，见下方"图案校验与工具脚本"。

### 核心算法

- **提示推导**（`PuzzleGenerator`）：`clue[r][c]` = 以 (r,c) 为中心的 3×3 窗口内涂黑格数量，越界部分不计。
- **唯一解校验**（`PuzzleSolver`）：回溯 + 约束传播。先用"必涂/必空"规则推导收敛解空间，推不动时再分支猜测；关卡生成后必须通过"解唯一"校验。
- **稀疏提示生成**（`PuzzleGenerator` + `PuzzleSolver`）：从全量提示出发，按"贪心去提示 + 解唯一校验"逐个删去可省的提示，让棋盘清爽、留出推理空间，同时保证谜面仍然只有唯一解。
- **精确错误检测**（`Validator`）：按答案逐格比对，只标红玩家已提交但画错的格子（误填的涂黑 / 误标的空白），未决定的格子不报错。
- **已满足提示检测**（`Validator`）：提示格周围 3×3 窗口内没有未决定的格子且涂黑数恰好等于提示值，说明该提示已"用完"，数字变绿反馈。

### 🖼️ 关卡图案

所有 11 幅像素画（红心 / 笑脸 / 蝴蝶 / 苹果 / 小房子 / 小鱼 / 星星 / 皇冠 / 月亮 / 火箭 / 城堡）都经过**逐格校验**：
小图手写 ASCII（`X` 涂黑 / `.` 空白），大图用 `fillRect` / `fillTriangle` / `fillEllipse` 等程序化作画；
月亮用满月 + 陨坑（比月牙更干净），星星用实心五角星，皇冠手写保证左右对称，小鱼尾巴与身体自然相连。
每幅图案都确保居中、对称、一眼可辨，并经渲染脚本在终端逐幅核对。

### 🛠️ 图案与工具脚本

`tools/` 目录是配套开发工具，用于**重新生成 / 校验**内置图案与稀疏提示：

| 脚本 | 作用 |
|------|------|
| `render_patterns.py` / `final_patterns.py` | 把图案渲染成终端字符画，肉眼核对造型 |
| `gen_clues.py` | 从图案答案出发，贪心去提示 + 唯一解校验，生成稀疏提示 |
| `verify_clues.py` | 解析 `SparseClues.kt`，逐个关卡校验提示集是否仍唯一解 |
| `update_clues.py` | 把生成的提示集安全写回 `SparseClues.kt` |

修改图案后的标准流程：改 `Levels.kt` → 跑 `verify_clues.py` 看哪关失效 → `gen_clues.py <关名>` 重生成 → `update_clues.py` 写回 → `./gradlew testDebugUnitTest` 最终把关唯一解。

## 🛠️ 构建与运行

### 环境要求

| 依赖 | 版本 |
|------|------|
| JDK | 21+（AGP 9.x 强制要求） |
| Android SDK | compileSdk 36 |
| Gradle | 项目自带 Gradle Wrapper |
| Android Studio | 最新稳定版 |

### 运行步骤

1. 使用 Android Studio 打开项目根目录；
2. 等待 Gradle 同步完成（首次会自动下载依赖）；
3. 连接设备或启动模拟器，点击 Run ▶️。

### 命令行构建

```bash
# 运行单元测试
./gradlew testDebugUnitTest

# 构建 Debug APK
./gradlew assembleDebug
```

> 若出现 "Unable to download toolchain" 错误，请先安装 JDK 21，并在 Android Studio 中将 Gradle JDK 设置为 JDK 21。

## 🧪 测试

核心逻辑单元测试位于 `app/src/test/java/com/example/xiangsugame/model/CoreLogicTest.kt`，纯 JVM 运行，覆盖：

1. 关卡唯一解 —— 每个内置关卡必须只有一个解且与答案一致
2. 提示推导 —— 3×3 窗口计数规则
3. 三态循环切换 —— 空白 → 涂黑 → 标记空白 → 空白
4. 胜利判定 —— 与答案逐格比对
5. 精确错误检测 —— 只标红真正画错的格子（含中间态不误报）+ 已满足提示检测
6. 撤销 / 重做 —— 指令栈语义
